# 中文用户指南

[README](../README.zh-CN.md) · [部署门禁](DEPLOYMENT.zh-CN.md) · [AI 维护](AI-HANDOFF.md) · [验证记录](VALIDATION-2026-09-09.md)

本文面向已经完成独立部署审批的操作员，解释按钮影响与失败处理，**不是安装、凭据读取、网络变更或公开发布授权**。当前公开副本的离线回归与合成包检查见验证记录，已认证真实 GUI 和目标部署另行验收；请勿把教程当成已验证的部署结果。

## 1. 入口、登录与授权

公开拓扑只使用 `router_a` / `192.0.2.10`、`router_b` / `192.0.2.11`、worker `192.0.2.20`；这些是文档地址。实际入口来自操作员私下核实的渲染配置，不要尝试把示例当在线服务访问。

- 先核对入口、目标范围、传输保护、当前身份和允许操作。只读验收不包含更新、保存、链式应用、转换应用或重启。
- Digest 默认 SHA-256；旧 MD5 兼容需明确安全审批，不能为了登录方便自行启用。
- **Digest + HTTP 不加密正文。** 配置、订阅、代理密码或 token 仍可能被传输路径上的观察者读取。管理网限制不是加密；敏感输入前确认可信传输范围，必要时使用经审查的 TLS 或获准的现有加密隧道。
- 精确 Host、Origin、客户端网段、认证与一次性写入授权是不同门禁。403 或认证失败时核对入口/来源，不扩大网段、不用通配、不绕过证书验证。
- 读取/生成/轮换密码、HA1、私钥，或访问 Keychain、剪贴板，须另有授权；读取权限不包含输出权限。不要把真实值放进 URL、浏览器日志、Issue、截图或仓库。

## 2. 页面状态与操作层次

页面有六个面板：**快速更新、域名/IP 与 Fake-IP、链式代理、配置浏览与修改、主配置回滚、订阅转换**。

- 切换面板不代表保存草稿，也不取消已经发出的请求。页面草稿不是可靠的持久保存；刷新/关闭前自行确认是否需要在获准的私有位置保留。
- 阅读每个目标自己的结果。两个目标串行写入，不是跨设备原子事务；后一个失败不能证明前一个未写或已撤销。
- 忙碌锁用于避免重复请求，不是安全审批。不要双击或用刷新来“确认”写入。
- 认证/连接失效后，旧读取和预览证明作废；晚到响应不能恢复旧 PASS。重新登录不自动重放写入，先重新读取当前目标。
- 部分快速更新按钮点击即提交，不保证存在第二次弹窗。必须在点击前确认目标、动作与可能重启的批准。

| 状态 | 应如何处理 |
| --- | --- |
| `PASS` | 只认可该结果明确覆盖的层次、目标和输入 |
| `FAIL` | 存在已观察到的失败；保留脱敏原因，不推断自动恢复 |
| `HOLD` | 门禁未满足；诊断缺失、漂移、锁或兼容性，不绕过 |
| `UNKNOWN` | 当前结果不可确认，尤其写入可能已经生效；先读回再决定 |
| `NOT RUN` | 未执行或本记录无相应证据；不能当作 PASS |

检查、预览、批准、写入、运行生效和恢复分别确认。HTTP 200、生成了链接、按钮变绿或 `COMMITTED` 回执都不能单独证明真实业务流量健康。

### 先选功能，再改设置

| 你想做什么 | 使用入口 | 先做什么 / 会改变什么 |
| --- | --- | --- |
| 重新拉取订阅、生成主配置 | 快速更新 | 先刷新两端状态；按钮是写操作，可能重启，不是纯检查 |
| 指定网站或 IP 走直连/代理，排除 Fake-IP | 域名/IP 与 Fake-IP | 先读取统一视图；只添加必要条目，检查顺序再确认 |
| 给某个静态节点增加独立出口 | 链式代理 | 选一个目标并读取；先验证，再应用、测试，取消也有独立流程 |
| 查看或手工修改 YAML | 配置浏览与修改 | 读取所选目标/文件后编辑；保存静态文件不等于运行态生效 |
| 恢复上一份主配置 | 主配置回滚 | 核对目标与可信备份；不等同于撤销链式或恢复流量 |
| 转换、整理、导出订阅 | 订阅转换 | 先区分生成链接、实际转换、下载与单目标应用；预览不写设备 |

顶部“三步看懂操作”和各面板“为什么 / 有什么区别”可点击或聚焦后按 Enter 展开；默认折叠只是减少干扰，不是省略确认步骤。读取、预览/检查、写入、重启用不同文字标签区分，不能只靠按钮颜色判断风险。

### 外观随系统与状态时间

- 界面自动跟随浏览器提供的系统浅色/深色偏好；系统外观改变后即刻更新，不需要刷新，也不会清空草稿、提交表单或重新读取设备。
- 没有单独主题开关或浏览器存储项。若颜色未变，先检查系统/浏览器是否强制外观；不要为切换主题刷新有未保存草稿的页面。
- YAML 编辑区在两种外观下都保持深底高对比，便于连续编辑，这是有意设计。
- “本页读取于”是本次成功获取状态的浏览器本地时间，不是服务器采样时间，也不证明状态此刻仍未变化。失败后会变为“状态未确认”；操作前重新读取，不把旧 ACTIVE 当作运行验收。
- 键盘焦点、错误、禁用与确认提示在两种外观下均保留；减少动态效果/高对比偏好沿用系统设置。

## 3. 快速更新

本面板的主配置更新与两个来源更新入口都是**双目标写操作**；“检查并更新”不是只读检查。需要批准真实取源、目标文件变更及相应重启风险。不要因为编辑器把 source/base 标为只读，就把来源更新按钮理解为只读。

### 主配置更新

通常流程为：生成新 Candidate → 绑定本次候选摘要 → 校验 → 保存可恢复基线与分组选择 → 重放当前定制 → 替换主配置 → 按结果验证。

- 内容变化时可以受控重启 OpenClash，并尝试恢复仍存在的选择；它不切换 ACTIVE 或写 UCI。
- 主文件没变时不因本次替换而重启，但其他已定义的检查仍可能执行。
- 校验失败、网络中断或恢复尝试都要看各目标回执；“尝试恢复”不是“已恢复”。
- 来源更新、Candidate 准备、主配置替换是不同动作。阅读实际按钮的目标/文件说明，不连点多个更新来代替诊断。
- 事务后的备份保留/清理是独立结果；清理警告不自动否定或撤销已经完成的配置提交。

**风险：** 双端部分完成、短时断流、取源数据漂移。**恢复：** 先分别读回目标与事务结果，再使用该目标可信、兼容的恢复路径；不盲目重试。

## 4. 域名/IP 分流与 Fake-IP

### 建议顺序

1. 读取两个目标，确认主配置与定制状态的 SHA-256 基线均有效；读取失败时不要使用旧视图。
2. 分清只读并集、工具拥有的条目、来源/基础配置已有条目和冲突。统一视图不代表两端内容完全相同。
3. 编辑最小必要项，检查顺序、策略、所属目标与重复/冲突提示；检查全部语法。
4. 获准保存后提交；两端分别预检、分别提交，CAS 会拒绝覆盖已变化的基线。
5. 分目标核对静态文件、定制回执、运行态与选择；不要用页面一次成功覆盖部分失败。

### 输入与所有权

| 类型 | 合成示例 | 边界 |
| --- | --- | --- |
| DOMAIN | `service.example.invalid` | 精确域名，不填 scheme、路径或端口 |
| DOMAIN-SUFFIX | `example.invalid` | 后缀匹配范围比单一主机广，先核对影响 |
| IP-CIDR | `192.0.2.0/24` | 文档网段；不是更改系统路由或防火墙 |
| IP-CIDR6 | 使用经验证的 IPv6 CIDR | 遵循表单校验，不用主机名代替网段 |

策略只选当前目标已存在且适用的策略/分组。IP 规则的 `no-resolve` 语义、原 rank/order、精确原文及非本工具所有的条目必须保留；不能为了统一视图而排序、接管或静默删重。编辑不变或取消不应改变规则优先级。

Fake-IP Filter 控制相应 DNS 处理，不等同于 DIRECT 分流规则，更不证明端到端连通性。新增前检查来源已有条目与重复/冲突；删除只针对明确归本工具管理的项目。

“实时判路与通道可达性”依赖有限的已知上下文。DNS、GeoIP、provider、当前选择或其他条件无法确认时保持 `UNKNOWN`/上下文受限；不能把一次通道探针当成所有业务路径证明。

## 5. 链式代理

方向为：**设备 → 已有原节点 → 落地代理 → 目标服务**。落地代理必须已经存在并获准使用；操作台不购买、开通或部署代理服务。

### 支持与限制

- 落地协议支持受约束的 SOCKS5、HTTP/HTTPS CONNECT、Shadowsocks AEAD；以当前协议校验结果为准。
- 仅支持受支持的静态节点和单层关系。已有 `dialer-proxy`、动态 provider、多层链或会通过 `include-all` 暴露内部节点的结构可能被拒绝，不要手改内部节点绕过。
- 读取节点与链式状态，确认目标、原节点、落地身份/协议、TLS 设置和基线；检查通过且获准后再应用。
- 密码不回显不代表无密码落盘。真实配置和受保护备份需要保存运行所需凭据；不能放进公开样例或截图。
- 保留旧密码仅在类型、地址、端口、认证等身份字段完全一致并显式确认时可用；身份改变后必须重新输入，不接受掩码文字代替密码。

### 应用、探针与取消

应用是配置/可能运行态变更，不是读取。核对每端结果，区分：静态配置关系、runtime 中的关联、原节点可达性、完整链路探针。固定 TCP/HTTPS 探针不证明所有站点、UDP、出口运营商或住宅身份；不要用结果作此类保证。

取消时使用正常“取消所选链式代理”流程，恢复受管原节点后再验证。主配置回滚会重放当前定制，**不等于取消链式**。不要直接删内部节点、清状态文件或移除锁。

**降级门禁：** 在仍能识别链式状态的当前版本中取消链式并验证恢复，才考虑降级到旧版；不能先降级后指望旧程序清理新格式状态。

## 6. 订阅转换工作台

### 生成链接与实际执行不同

- “仅生成订阅链接”“校验链接参数”“从链接恢复参数”只处理参数/格式，不取源，不证明来源或后端可用，也不代表已转换。
- “实际转换并预览”可能通过服务端执行器访问已批准来源；输入文件与远程 URL 同样可能含敏感数据。
- `auto` 仅用于生成交给外部识别的链接；实际执行必须选择服务端支持的明确目标格式。
- 自定义后端 URL 不是任意网络访问权限。实际执行由服务端固定、受控的执行器完成，不把浏览器输入直接变成任意内部后端请求。
- 切换预设、恢复生成版本或手动编辑结果前，确认当前输入/输出是否会被替换；拒绝预设变更应保留原草稿和仍有效的状态。

### 在线取源与断网执行的边界

在线取源限受控公网 HTTP(S) 的 80/443，逐跳检查 URL authority、DNS 与实际连接地址、TLS、重定向、大小和超时。拒绝私网、loopback、保留/metadata 地址、混合 DNS 结果及 HTTPS 降级；不要关 TLS、放宽 SSRF 或改用另一地址绕过拒绝。

取源完成后的高级脚本/转换执行在断网、非 root、资源受限的短命容器中进行，并有限制输入、输出、并发与时限。**容器断网不等于整个转换流程没有联网**。镜像来源和 digest、所用脚本/模板以及远程资源仍须独立审查授权。

### 保真与兼容

- 目标格式只接受明确支持的字段和协议。遇到不支持或无法保真的字段，应明确拒绝，不静默丢节点或把失败包装成成功。
- JSON/Surge 等转换检查严格类型、预算和语义；页面能展示正文不证明目标客户端接受。
- Mellow 仅覆盖可保真的 Shadowsocks/JSON VMess 子集；不是所有协议/字段的通用输出器。
- 规则集转换、模板渲染等工具不是路由器 apply；使用远程资源或脚本仍遵守取源/隔离门禁。

### 草稿、下载与敏感内容

输入档案是**未加密 JSON 草稿**，不是凭据保险箱，也不含运行证明。它可能包含敏感订阅/参数，只在明确许可下保存到私有位置；操作台不自动持久保存这些输入。复制和下载会把内容交给剪贴板或文件系统；清空页面不会清除已有下载、剪贴板、客户端状态或第三方副本。

失败后仍可看到的旧结果不代表本次转换成功。核对来源、目标格式及状态；不能把旧正文继续当作新预览的证明。

### 将 Clash 结果保守合并到一个目标

1. 取得当前转换结果，确认手工编辑的正文就是计划使用的版本。
2. 选择**一个**目标、来源角色、合并模式与目标分组；默认 `nodes`，可选受约束的 `merge`。
3. 读取当前基线并生成预览；检查新增、保留、冲突和拒绝原因，取得本次应用授权。
4. 预览绑定来源、目标、mode、group、当前结果正文、baseline/plan 摘要。任何相关输入变化都须重新预览；改回旧值不恢复 proof。
5. 提交后逐项读回。proof 在尝试发送后即按已消费处理；即使响应丢失或为 `UNKNOWN`，也不能复用。

合并默认保留既有 DNS、TUN、监听、认证、provider 与网络设置，拒绝冲突或循环引用，不整份覆盖运行网络配置。CAS 漂移时重读和重新预览，不强制替换。`no_change=true` 只表示本次没有写入/重启，不是 runtime PASS。

## 7. 外部服务与本机客户端

短链、Gist、客户端导入都不是转换流程的默认后台动作。每次明确：**接收方、会发送的数据、是否需要敏感读取，以及具体读取/创建/更新/删除/公开范围**。界面的确认框不扩大操作员或 AI 已获授权。

- 只读第三方请求也可能把订阅参数、标识或内容发给对方，不能以“GET”或“内网”作为豁免。
- Secret Gist 只是非列表展示，不是访问控制；持有链接者可能读取内容。
- Gist 删除针对整个指定 Gist，不是仅清空页面或一条结果。确认对象与删除范围；写入超时先查询第三方实际状态，不重复 POST。
- “导入本机 Clash”会唤起本机客户端，由客户端取源；它不自动应用到两个路由器。先确认客户端、来源和导入影响。
- 页面清空不撤销外发，不删除第三方内容，不清系统剪贴板或下载文件。外部撤销/删除需单独确认。

## 8. 配置浏览、手工保存与主配置回滚

编辑器中的 source/base 只读；仅允许受管白名单中的主配置编辑。读取后保留每个目标的基线，检查文件角色、YAML、大小/结构预算及 Mihomo 校验。保存使用 CAS 和事务锁；漂移时拒绝覆盖。

**手工保存主配置和“回滚主配置”只更新静态文件，不自动 reload/restart。** 若需让运行态加载它，另行核实活动指向、审批影响并采用受控流程；不能因为保存成功就宣称流量已使用新配置。

回滚选择必须属于当前目标、来源可信、完整且与当前版本兼容。回放当前定制后，结果不一定等同于备份原始字节；它不是取消定制或链式，也不是运行态恢复证明。受管保留/清理回执与提交回执分别读取；新增定时任务或删除备份需要另行批准。

## 9. 出错时如何停止

| 现象 | 下一步 |
| --- | --- |
| 缺读取摘要、CAS 漂移、预览失效 | 重新读取/预览，复核差异并重新确认，不强制提交 |
| 401/403、认证失效 | 保留当前草稿但作废旧证明；核对身份与精确入口，不放宽门禁 |
| `UNKNOWN`、连接中断、写入超时 | 不自动重试，先读回该目标/第三方状态与回执 |
| A 成功、B 失败 | 分目标处理；不推断两端自动回滚 |
| 锁占用、PENDING/PREPARED、恢复待确认 | 保留现场并交由获准维护者诊断，不删锁/备份/目录 |
| `HOLD=LEGACY_LAN_MIGRATOR_DISABLED` / exit `64` | 旧 LAN 入口已禁用，不是更新成功；交由维护者使用 `install_worker_web_console.sh` / `update_worker_web_console.sh`，不得换摘要绕过 updater |
| 备份清理警告 | 与配置提交分开核对，不把清理失败变成重复 apply |
| 探针成功但业务仍失败 | 继续独立检查运行态、DNS、实际路径与所需协议，不能扩大 PASS |

报告问题只提供可公开的版本信息、合成复现、脱敏原因码及明确的已做/未做范围。不要提交真实配置、来源链接、密码、token、私钥、生产摘要、主机进程或备份标识。更多维护约束见 [AI-HANDOFF.md](AI-HANDOFF.md)。
