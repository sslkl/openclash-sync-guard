日常操作

快速更新

更新各自的订阅文件，或重新生成两边主配置。按 路由器 A、路由器 B顺序执行，不把一边的订阅复制给另一边。

打开 Nexitally 官网 ↗

先核对，再更新 下方按钮会更新两个子网，不是只读检查。先使用顶部“刷新状态”，再选择需要更新的文件；两边回执要分开核对，任一边失败时先排查，不要重复点击写入。

该点哪个按钮？更新后会发生什么？
  1. 机场节点刚有变化：选择对应的“更新 Maying”或“更新 Nexitally”，只更新两边各自的机场文件。
  2. 要把最新来源合入主配置：需要时先更新机场文件，再点“检查并更新”。它会生成 Candidate（候选）、校验、备份，再更新静态主配置。
  3. 内容真的变化时：主配置更新会受控重启 OpenClash，期间连接可能短暂中断；不要关闭页面或重复点击。
  4. 结束后：分别检查两边的写入、重启与校验回执，再确认常用网站能否正常访问。任一边失败时先核对当前状态，不自动重试。

独立定制

域名/IP 分流与 Fake-IP Filter

让指定域名或 IP 走指定策略，或让部分域名使用真实 DNS 结果。自定义分流优先于订阅规则，保存会影响两个子网。

先读取 → 编辑 → 检查 → 勾选确认 → 保存。相同匹配条件但策略不同会停止并提示；保存时按读取摘要做并发保护。遇到冲突或摘要变化时，先核对草稿和当前内容，不要反复保存。
规则类型、填写示例与常见误区
只匹配一个域名
用 DOMAIN，如 api.example.com；不填写 https://、路径或端口。
整个域名及其子域名
用 DOMAIN-SUFFIX，如 example.com；不需要加 *。
匹配 IP 网段
IPv4 用 IP-CIDR，IPv6 用 IP-CIDR6。地址和掩码必须构成有效网段。
只想绕过 Fake-IP
添加到下方 Filter，而不是分流规则。Filter 影响 DNS 返回值，不决定走哪个代理。

策略选 DIRECT 表示直连。两个子网同一匹配条件策略不一致时会停止；先处理冲突，不靠再次保存覆盖。完整规则区只读，新增和修改使用下方编辑区。

只作用于所选子网 先读取并选择节点，检查后确认应用。保存不等于连通；需要验证时，请主动使用下方“测试所选已保存链路”。测试为 UNKNOWN（无法确认）或失败时，不要当作链路可用。

          
什么是链式代理？需要准备哪些信息？
你的设备→原节点→落地代理→网站
落地必须是已经运行的 SOCKS5、HTTP(S) 或 Shadowsocks 服务。只有一个家宽 IP 或服务器 IP，不能自动成为代理。
  1. 选择目标子网并读取节点，再选需要新增出口的原节点。
  2. 按服务提供的信息填写地址、端口、协议和认证；TLS 会校验证书。
  3. 检查并确认影响后保存，再单独测试已保存链路。测试只证明本次固定探针结果，不证明住宅出口身份或所有网站可用。
  4. 想恢复时，选择原链路并“取消链式”。不会改动另一子网，也不会删除原节点。
密码不回显；修改连接身份后需重新输入，不要把订阅链接填进落地地址。

生成链接、实际转换、下载和应用有什么区别？
生成链接
只生成一条带参数的转换 URL，不验证源是否可达。链接可能含订阅凭据，不要公开分享。
实际转换
把本次输入提交给同步器，受控取源后在隔离执行器转换。先确认目标客户端，再核对输出的节点与规则。
下载 / 复制
把结果交给你，不写入路由器。结果是敏感配置，妥善保管。
应用到路由器
在独立区域选择单个目标、生成预览并确认。默认只追加节点；合并规则是另一种显式模式，不要把格式检查当作安全审计。
不确定的进阶参数保持默认。远程模板、短链和 Gist 等外部服务会扩大数据访问范围，只有在理解接收方和影响后才使用。

回滚只替换静态主配置并重放当前定制项；不会切换 ACTIVE（当前启用配置）、写入 UCI（OpenWrt 配置接口）或 reload（重新加载）运行内核。可信的新格式备份仍遵循七天保留策略。
